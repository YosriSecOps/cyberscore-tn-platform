Slide 09 / 32 — Moteur d'Audit

L'évaluation sur 16 piliers

محرك الفحص التقني غير الاقتحامي — تفصيل الـ 16 مؤشراً

09 / 32
1. Chiffrement SSL/TLS (12%)

Négociation TLS 1.2/1.3, suites cryptographiques ECDHE, validité TunTrust.

2. En-têtes HTTP (10%)

Contrôle strict de HSTS (min 6 mois), X-Frame-Options (anti-clickjacking), nosniff.

3. Politique CSP (8%)

Content Security Policy, interdiction d'unsafe-inline et d'unsafe-eval.

4. Cookies de Session (7%)

Drapeaux obligatoires : HttpOnly, Secure, SameSite=Lax/Strict.

5. Hygiène DNSSEC (6%)

Validation DNSSEC, serveurs NS faisant autorité, refus de transfert AXFR.

6. Sécurité E-Mail (6%)

Protection anti-usurpation d'État : SPF (v=spf1), DKIM et DMARC (p=reject).

7. Surface Réseau (8%)

Détection passive des ports d'administration ouverts (SSH:22, RDP:3389, Telnet:23).

8. Fuites d'Infos (5%)

Suppression des bannières Server, X-Powered-By et fichiers de config publics.

9-16. CTI & Avancés (38%)

Cartographie des sous-domaines, réputation IP, supply chain JS et CVEs.

⚙️ /etc/nginx/conf.d/cyberscore.conf
server {
  listen 443 ssl;
  server_name cyberscore.tn;
  ssl_certificate     /etc/nginx/ssl/cert.pem;
  ssl_certificate_key /etc/nginx/ssl/key.pem;

  # ─── Sécurité Headers ─────────────
  add_header X-Frame-Options DENY;
  add_header X-Content-Type-Options nosniff;
  add_header X-XSS-Protection "1; mode=block";

  # ─── Routage API → VM 2 Backend ───
  location /api/ {
    proxy_pass http://192.168.98.149:8000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
  }

  # ─── Routage Frontend → Next.js ───
  location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
  }
}
🔑 Pourquoi Nginx est Architecturalement Obligatoire
❌ Sans Nginx

Cookie déposé par :149:8000 ≠ envoyé à :150:3000. Deux origines = cookie invalide.

✅ Avec Nginx

Tout passe par cyberscore.tn. Un seul domaine = cookie HttpOnly valide partout.

Slide 27 / 32 — Sécurité Offensive & Modélisation des Menaces

Résilience du QR Code face au Phishing

نمذجة التهديدات السيبرانية وإحباط فخ تزوير رمز الاستجابة السريعة

27 / 32
🎯 1. Le Piège du Domain Mismatch (Domain Binding)

Le QR code encode l'URL ANCS liée au domaine officiel. Au scan sur smartphone, la page affiche : « Certifié exclusivement pour : sante.gov.tn ». La victime constate immédiatement la divergence avec sante-fake.com sur son PC : l'usurpation est démasquée en 1 seconde !

🏛️ 2. Ancrage Souverain .tn & Certificat TunTrust

Impossible d'obtenir un faux domaine sous .tn (géré par l'ATI/ANCS) ni un certificat étatique TunTrust AS2609. Et tout faux site soumis à l'audit CyberScore est recalé d'office avec un Grade F (0/100) — DOMAINE SUSPECT.

🔒 3. Contrôle d'Origine Dynamique (Widget JS)

Le widget client vérifie en temps réel window.location.hostname et l'en-tête HTTP Referer. En cas d'appel illégitime hors du domaine homologué, le sceau vert est révoqué au profit d'un avertissement d'invalidité.

⚡ THREAT MODELING // LE PIÈGE DU DOMAIN MISMATCH
1. Attaquant sur PC : Affiche sante-fake-tunisie.com avec capture volée du QR Code.
▼ Scan par le smartphone de la victime
2. Mobile Victime : Ouvre cyberscore.tn/fr/verify/sante.gov.tn (Serveur ANCS).
▼ Comparaison visuelle instantanée
3. RÉSULTAT FATAL POUR LE PIRATE : Le citoyen lit sante.gov.tn sur son mobile ≠ sante-fake sur PC. L'arnaque s'effondre immédiatement !

Slide 29 / 32 — Sécurité des Sessions & Anti-XSS

Migration vers les Cookies HttpOnly

تأمين جلسات المستخدم — الانتقال من التخزين المحلي إلى ملفات تعريف الارتباط المحمية

29 / 32
❌ AVANT : localStorage (Vulnérable)

Un attaquant exploitant une faille XSS pouvait voler le token en 1 ligne de JS : localStorage.getItem('cyberscore_token'). Le token était visible, copiable et exportable par n'importe quel script injecté.

✅ MAINTENANT : Cookie HttpOnly (Immunisé)

Le cookie est géré uniquement par le navigateur au niveau noyau. JavaScript ne peut ni le lire, ni le modifier, ni l'exfiltrer. Même en cas de XSS, le token est invisible et intouchable.

🔒 HttpOnly

JS ne peut pas lire le cookie — Anti-XSS total.

🛡️ Secure

Envoi HTTPS uniquement — Anti-interception réseau.

⚡ SameSite=Lax

Bloque l'envoi depuis sites tiers — Anti-CSRF.

⏰ Max-Age=86400

Expiration automatique 24h — Session bornée.

⚙️ Implémentation Backend (FastAPI)
response.set_cookie(
  key="cyberscore_token",
  value=access_token,
  httponly=True,     # JS bloqué
  secure=is_https,   # HTTPS only
  samesite="lax",    # Anti-CSRF
  max_age=86400,     # 24h auto
  path="/"
)
🌐 Implémentation Frontend (Next.js)
const res = await fetch(url, {
  credentials: "include",
  // ← Le navigateur envoie
  //   automatiquement le cookie
});
✅ Validation Production (curl)
# Login → Cookie HttpOnly déposé ✅
curl -k https://cyberscore.tn/api/auth/login
→ Set-Cookie: cyberscore_token=...;
  HttpOnly; Secure; SameSite=lax

# Logout → Cookie révoqué ✅
curl -k https://cyberscore.tn/api/auth/logout
→ Set-Cookie: Max-Age=0
POURQUOI NGINX UNIFIE TOUT SOUS UN SEUL DOMAINE ? Les cookies sont liés au domaine, pas à l'IP. Sans Nginx, le cookie déposé par 192.168.98.149:8000 ne serait pas envoyé à 192.168.98.150:3000. Le reverse proxy unifie tout sous cyberscore.tn → le cookie est valide partout.
